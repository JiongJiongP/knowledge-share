RRF 混合搜索深度剖析

Elasticsearch BM25 + Qdrant 768d 向量语义搜索 → RRF 融合排序

graph LR Q["用户查询"] --> ES["ES multi_match
title^3 + body"] Q --> Qd["Qdrant embedding
cosine similarity"] ES --> BM25["BM25 排序列表"] Qd --> Vec["向量排序列表"] BM25 --> RRF["RRF Fusion k=60"] Vec --> RRF RRF --> Result["融合结果 · 分页返回"] style Q fill:#5c6bc0,color:#fff style RRF fill:#e65100,color:#fff style Result fill:#43a047,color:#fff

RRF 公式: score(d) = Σ 1/(k + rank_i(d))

搜索方式查准率查全率语义理解
ES BM25 关键词高低无
Qdrant 向量语义中高强
RRF 混合融合高高强

为什么需要混合？

  • 搜索 "K8s 网络排查" → BM25 命中 title
  • 搜索 "容器编排通信故障" → 向量召回语义相近内容
  • 双方互补，RRF 无需调权即可公平融合

搜索联动的三个设计决策

  1. 冗余设计：content 表同时维护 MySQL FULLTEXT 索引 + ES 索引文档，MySQL 做精准查询，ES 做全文检索
  2. 覆盖索引：
    idx_status_del_pub(status, is_deleted, published_at)
    列表查询仅扫描索引，不回表
  3. 渐进式迁移：12 次 Flyway 迁移，字段随着搜索需求逐步扩展，非一次设计到位

SM4 国密全栈加密

配置文件 → 数据库存储 → 传输层，三层 SM4 保护

L1 · 配置
EncryptedPropertyPostProcessor 解析 SM4(...) 占位符 → Spring Boot 启动期自动解密注入
服务器仅需一个环境变量：SM4_KEY
L2 · 存储
MyBatis-Plus BaseTypeHandler 透明加解密
确定性加密（username/email，支持 WHERE 等值查询）· 随机 IV 加密（displayName，仅展示用）
L3 · 传输
HTTPS/TLS 1.3 + JWT 签名 + 前端 DOMPurify 防御 XSS
字段加密模式IV 策略WHERE 查询密文存储
username确定性 SM4/CBCSHA-256(明文)[0:16]✅ eq 匹配VARCHAR 256
email确定性 SM4/CBCSHA-256(明文)[0:16]预留VARCHAR 256
displayName随机 IV SM4/CBCSecureRandom— 仅展示VARCHAR 256

对业务代码 0 侵入 — Content / Social / Search 模块无需任何修改

AI 协作最佳实践

何时使用 AI

  • 需求澄清（brainstorming）
  • 方案设计（writing-plans）
  • 代码生成（subagent）
  • 测试编写（TDD）
  • 代码审查（code-review）
  • 安全审计（security-review）

何时不使用

  • 架构决策（需人工评审）
  • 业务规则变更（领域知识）
  • 生产调试（环境上下文）

选择策略：简单任务 → 直接执行 / 复杂任务 → brainstorming → writing-plans → subagent
