Brainstorming-Driven Design

真实案例：首页仪表盘设计

  • 触发：用户提出 "首页太单调"
  • brainstorming skill 介入：
    • 探索需求 → 追问问题 → 生成视觉伴生图
    • 提供 Option A / B / C 三种方案
  • 用户选择方案 A — 带统计卡片的仪表盘
  • 结果：设计文档自动提交至 Git，进入下一阶段

Plan-Driven Development

writing-plans skill 的输出特性

  • 每一步都是单一动作（2-5 分钟）
  • 精确的文件路径 + 完整代码（无占位符）
  • 预期命令和输出结果
  • 零歧义 — 人类或 AI 均可执行

秘密配置的透明加解密

问题

所有密钥硬编码于
application.yml
明文提交至 Git

方案

SM4/CBC/PKCS7
存储时加密
启动时自动解密

实现

EncryptedPropertyPostProcessor
解析 SM4(...) 模式

服务器仅需一个环境变量：SM4_KEY

AI 协作最佳实践

何时使用 AI

  • 需求澄清（brainstorming）
  • 方案设计（writing-plans）
  • 代码生成（subagent）
  • 测试编写（TDD）
  • 代码审查（code-review）
  • 安全审计（security-review）

何时不使用

  • 架构决策（需人工评审）
  • 业务规则变更（领域知识）
  • 生产调试（环境上下文）

选择策略：简单任务 → 直接执行 / 复杂任务 → brainstorming → writing-plans → subagent
